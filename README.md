# RIFT（仮称）
Electron + React + Vite で動く、4chan / 5ch の閲覧専用アプリです。
board -> thread -> post/gallery の流れで閲覧し、翻訳と画像保存に対応しています。
## 5ch の使い方
1. ヘッダーで「5ch」を選び、板・スレッドを選択します。板／スレッドURLの入力にも対応しています。
2. 返信参照のプレビュー・移動、ID絞り込み、NG ID・NGワード、AA表示、未読位置への移動を利用できます。
3. 「更新」で再取得します。短時間の連続操作はキャッシュを使用し、本文は可能なら差分取得します。自動巡回はしません。
4. 画像は初期状態では取得しません。外部接続の確認後、画像一覧・拡大表示・個別／選択／一括保存を利用できます。
画像対応は **i.imgur.com / i.postimg.cc / i.ibb.co のHTTPS直接リンク**に限定しています。JPEG・PNG・GIF・WebP、1枚8 MiB以下・1600万画素以下（各辺16384以下）が対象です。画像ページ、短縮URL、クエリ付きURL、リダイレクト、その他のホスト、動画には未対応です。画像ホストには接続元IPが伝わります。
画像は同一URLをまとめ、表示対象の投稿から最大2000件を扱います。一覧は12枚ずつ取得し、保存時は安全な生成ファイル名を使います。表示を停止しても、既に受け付けた通信は完了する場合があります。
5chは閲覧専用です。投稿・ログイン・UPLIFT・過去ログの完全対応は含みません。旧5ch.net URLは現在の公式板一覧に照合して5ch.ioの取得先へ解決します。サービス側の制限・変更により読めない板やスレッドもあります。
表示名はRIFTを仮採用しています。既存データを維持するため、内部パッケージ名とユーザーデータ保存先は変更していません。旧4chanの閲覧データは自動移行し、以後はサービス別にお気に入り・閲覧位置・NG設定を保存します。「閲覧データを消去」は両サービスに適用されます。
## 4chan の主な機能
- 板一覧の取得・検索
- カタログからスレッド一覧表示（先頭50件）
- スレッド表示（THREAD / GALLERY 切り替え）
- 画像の個別保存 / 一括保存
- 投稿テキストの日本語翻訳（DeepL）
- 過去スレの追加読み込み
- 画像のアプリ内拡大表示・左右移動、WebM の再生
- お気に入りの板・スレッド、既読表示、前回の選択とスクロール位置の復元
- 保存キャンセルの表示・二重実行防止・失敗したファイルだけの再試行
- 翻訳結果の一時キャッシュと原文のみ／訳文付きの表示切り替え
## 使い方の補足
- サムネイルをクリックするとビューアが開きます。左右キーで前後へ、Esc で閉じます。動画にフォーカスがある間は左右キーを動画のシーク操作に使います。
- 板の「登録」とスレッドの「お気に入り」で登録できます。お気に入りの板は左ライブラリに並び、スレッドは「お気に入りスレッド」から開けます。
- お気に入り・既読・前回の選択・スクロール位置は PC 内の localStorage に保存します（お気に入りは各200件、履歴は各サイト500件、暗号化なし、クラウド同期なし）。「閲覧データを消去」で削除できます。
- 既読は表示位置までの記録です。削除済みスレッドの復元や、追加で読み込んだ過去スレ自体の再読み込みは保証しません。
- 翻訳キャッシュは起動中のメモリだけに最大200件保持し、終了・画面再読み込みで消えます。原文や訳文を閲覧履歴へ保存しません。
- 保存の再試行では失敗したファイルだけを対象に、保存先を再選択します。キャンセルできるのは保存先選択時です。
## 必要環境
- Node.js 22.12 以上
- npm
- DeepL API Free のキー（翻訳機能を使う場合）
## セットアップ
```bash
npm ci
```
`.env` は自動読み込みしない実装です。実行前に環境変数 `DEEPL_API_KEY` を設定してください。
### Windows (PowerShell)
```powershell
$env:DEEPL_API_KEY="your_deepl_api_key"
npm run dev
```
### macOS / Linux (bash/zsh)
```bash
export DEEPL_API_KEY="your_deepl_api_key"
npm run dev
```
永続化したい場合は、OSのユーザー環境変数に `DEEPL_API_KEY` を登録してください。
登録後はターミナルや起動元のアプリを再起動してください。既に登録済みなら再設定は不要です。
キーをソースコードや共有ファイルに書かないでください。環境変数は暗号化された秘密保管庫ではありません。
翻訳・画像保存・5ch閲覧は Electron アプリ内で利用できます。DeepLキーなしでも閲覧できます。Vite の画面を通常のブラウザで開いただけでは利用できません。
## 実行コマンド
- `npm run dev`: 開発起動（Vite + Electron TS watch + Electron app）
- `npm run lint`: 型チェック
- `npm test`: 翻訳・保存・IPC のセキュリティ回帰テスト（実際の API キーや外部通信は不要）
- `npm run build`: Renderer/Electron をビルド
- `npm run electron`: ビルド後に Electron 実行
- `npm start`: 既存ビルドを実行
初回および更新後は `npm run electron` でビルドして起動してください。
生成物の `dist/` と `dist-electron/` は Git に含めません。
開発時はポート 5173 を使用します。Electron 側のコードを変更した場合は開発プロセスを再起動してください。
## セキュリティ方針
- DeepL APIキーの直書きは禁止（環境変数のみ）
- 投稿本文はプレーンテキスト表示（HTMLを直接挿入しない）
- 翻訳・画像保存用のローカル HTTP サーバーは起動しない
- 翻訳・保存は送信元を検証した IPC 経由でメインプロセスが実行
- 4chanの画像保存先の通信は `https://i.4cdn.org` の所定の画像・動画パスのみ許可し、リダイレクトを拒否
- API キーはメインプロセスだけで使用し、画面やエラー応答へ渡さない
- 5ch本文・外部画像は検証付きIPCで取得。許可ホスト・パスに限定し、DNSで内部ネットワークを排除。画像の形式・容量・寸法を検証してから表示／保存
- 外部画像URLは画面の画像要素へ直接設定しない
依存関係を変更した場合は `npm test`、`npm run lint`、`npm run build`、`npm audit` で確認してください。
ビルド後の `node tests/electron-smoke.cjs` は、非表示の Electron ウィンドウで起動と翻訳 IPC を検証します（通信は模擬応答、ユーザーデータは一時領域に分離）。
板の高速切り替え、ビューアのキーボード操作、保存キャンセル、閲覧状態復元・消去、デスクトップ／狭い画面も検証し、画像を `.test-artifacts/` に出力します。
## 自動チェック
`.github/workflows/check.yml` は push / pull request 時にテスト・型チェック・ビルド・Electron 操作テスト・依存関係の脆弱性検査・Gitleaks の秘密情報検査を行います。APIキーを GitHub Secrets に登録する必要はありません。
Gitleaks は現在のファイル全体と、キー失効対応時の `bb93b15` より後のコミットを検査します。それ以前の失効済みキーを含む履歴は対象外で、履歴自体を削除する仕組みではありません。検出値はログでマスクします。
Dependabot は npm と GitHub Actions の更新 PR を週次で作成します。Actions の実行許可や必須チェックの設定はリポジトリ管理者が管理してください。

## 追加機能（2026-10-05）

- 板・スレッドを選ぶとタブに追加します。同じ閲覧先は既存タブへ切り替え、最大20件まで開けます。×で閉じられます。
- タブ一覧はPC内に保存し、再起動後に復元します。スレッドの閲覧位置は既存の保存機能で復元します。非選択タブの自動通信は行いません。
- タブ切替時に画像取得への同意は解除されます。閲覧データ消去ではタブも消去します。本文・画像・認証情報はタブに保存しません。
- 5chの取得失敗時は公式板一覧で移転を再確認（最短60秒間隔）。登録ホストが変わった場合だけ1回再接続し、任意の転送先へは接続しません。403・429・サーバー障害・取得不能・未確認の転送を分けて案内します。削除とDAT落ちの原因は断定しません。
- ImgBBのHTTPS直接画像リンクに対応しました。[公式APIのURL形式](https://api.imgbb.com/)に基づきi.ibb.coのみ許可します。共有ページ・認証付きURL・転送先は対象外です。従来の容量・寸法・形式・DNS検証を維持します。


## ライブラリ（2026-10-14）

左側に「お気に入りスレッド」「閲覧履歴」「お気に入り板」「すべての板」をまとめました。ライブラリを切り替えても、右側の本文はそのまま読めます。以前の上部のお気に入り一覧は左側へ移動しています。

- お気に入りスレッド: タイトル・板名検索、全サイト／4chan／5chの絞り込み、登録順／最近読んだ順。既存タブがあれば再利用します。
- 閲覧履歴: 本文の取得・表示に成功したスレッドを各サイト最大500件記録し、今日／昨日／それ以前に分けます。スクロールだけでは最終閲覧日時を変えません。個別削除と履歴だけの全消去ができます。
- お気に入り板: サイトをまたいで左側に常設。上下ボタンで並べ替えられ、板一覧の取得失敗時も保存済みショートカットは残ります。
- 履歴設定: 「閲覧履歴 → 履歴の設定・消去」で記録を停止できます。停止中は新しい履歴・閲覧位置を記録しませんが、既存履歴・お気に入り・開いているタブ・前回の選択は残ります。完全なプライベートモードではありません。再開後は次に開いたスレッドから記録します。
- タイトル・板名・登録日時・最終閲覧日時・閲覧位置をPC内に保存します。お気に入り・履歴自体は本文を保存しません。本文を残したい場合は、下記の「本文を保存」を使ってください。一覧を開くだけでスレッド本文・外部画像の全件取得は行いません。
- 旧データは自動移行します。タイトル不明は板名・番号で表示し、取得できたときに補完します。旧履歴の日時は以前の閲覧位置更新時刻から引き継ぎます。既に上限で消えた履歴は復元できません。
- お気に入りは板・スレッドそれぞれ各サイト200件。履歴削除はお気に入りやタブを閉じません。「閲覧データを消去」は両サイトの閲覧情報・タブ・保存済み本文を消去します。

## スレッド本文の保存・外部リンク

- スレッド画面の「本文を保存」で、取得済みのそのスレッドの本文をPC内に保存します。同じスレッドを再保存すると置き換えます。
- 左の「保存済みスレッド」から検索・閲覧・個別削除・全削除できます。保存した本文を開く操作では通信せず、再起動後やスレッド取得不能時も保存時点の内容を読めます。通常閲覧へ戻ると再取得します。
- 保存対象は投稿番号・名前・日時・ID・本文です。画像・動画・訳文は含みません。画像は従来の保存ボタンで別途保存してください。NGで非表示の投稿も取得済みなら保存対象です。「Load older thread」で追加した別スレッドは含めません。
- 上限は1スレッド8MiB・10,000投稿、全サイト合計100件・50MiBです。上限時は既存データを消さず案内します。
- 本文はアプリのIndexedDBに保存します（暗号化・同期・ファイル書き出しなし）。ブラウザの保存領域削除やアプリ配置変更等で失われる場合があります。「閲覧データを消去」は保存済み本文も削除します。
- お気に入り板は名前・サイト・操作ボタンを1行に集約しました。長い板名はマウスを重ねると確認できます。
- 本文のHTTP/HTTPS URLは色付き・下線付きです。クリック時は「外部サイトへ遷移します」と接続先を表示し、「ブラウザで開く」を選んだときだけ既定ブラウザを起動します。初期選択はキャンセルです。画像の「Open full」にも同じ確認を適用します。
